# Penumbra VR Framework 1.0.14 — Requiem progression candidate

Prepared 2026-10-28. Local release candidate; headset progression validation
pending. This version has not been played by the developer in-game or in a VR
headset. It does not establish a complete Requiem playthrough.

## Changes

- Connect native jointed Grab to the existing Black Plague connected-body
  behavior. This addresses level09's cable and oil/barrel rope and also admits
  compatible multi-body and world-anchored props in the remaining levels.
  Preserve joints, fixed endpoints, native attachment/detachment permissions,
  scripts and release momentum. Free assemblies consume bounded wrist drive;
  anchored assemblies retain native angular constraint ownership.
- Revalidate fresh acquisition and live changes to mass/joints before driving
  a held body. Do not place a newly jointed body through the free-prop matrix
  route. Preserve native rejection of locked connections and script shutdown.
- Restore Black Plague's native-range activation fallback for fixed Lamps,
  including the final furnace button, with native Pick/Interact flags and
  occlusion. Dynamic lamps remain physical interactions.
- Prevent inert Object housings from winning VR contact ranking while keeping
  static buttons with native callbacks eligible.
- Respect script-disabled player ownership for VR turn, posture and movement.
  Connect VR Pause/UI-close to the original credits Escape query.

The previous level08 orb/keypad, sphere throwing, lever COM, slider endpoint,
movement, jump and input corrections remain included. No puzzle scripts, asset
masses, collision sizes, jump force, gravity or solutions are changed.

## Verification and limits

Full Framework builds and **83/83 host tests pass in both Debug and Release**.
Exact native windows, metadata and whitespace checks pass. The script ownership
change received independent review without blockers; combined final independent
review was unavailable because of an agent usage limit, so the remaining changes
received local review plus automated regression checks. Final installer/package
identities are in the [artifact record](1.0.14-validation.json). The exact Setup
passes EN/ES standalone extraction, all 403 embedded payload hashes, topology
A–F, update from 1.0.13, repair/exact restoration and 20 uninstall-safety cases
in isolated roots. The source archive matches all 1692 build-commit files and
its two pinned upstream source inputs. Overture passes 298 product checks.
No actual game installation was changed and no game was launched.

Actual-consumer tests cover fresh native Enter/Update/Leave, attachment refusal
and handoff, changed joints/mass, animation companions, disconnected bodies,
static/world anchors, wrist motion, turn plus lift, native deactivation, lamp
range/occlusion, inert/static callback selection, credits edges/keyboard
fallback, script ownership and native travel carry. Shipped-Newton fixtures
exercise gravity-bearing 2/6/7-body components and a world anchor through the
production adapter. These fixtures do not execute the authored puzzle scripts.

The audit traces 219 entity references in levels09–11 to 88 direct definitions
and nine break variants. Native static-button callbacks, fuse/card/barrel
StickAreas, the alternate-ending area and script-to-credits routes remain
game-owned. See [capability evidence](../TRILOGY_PARITY_PLAN.md#remaining-requiem-levels--static-progression-audit)
and the [headset procedure](../VR_HEADSET_TEST_CHECKLIST.md#requiem-level09-cable-acceptance).

Actual cable/rope puzzle completion, authored constraint stability, impact
breaks, moving-bridge contact and ending transitions require a pinned headset
run. Level04 water/crouch recovery and the intermittent SDL startup crash remain
unresolved; this candidate does not claim to fix them. Other controller/device
and clean-PC acceptance remain independent.
